# 2026-09-16

## 排查：transfer 登录后新会话的低代码功能选择面板消失

**现象**：从 `/login/transfer` 登录进来的新会话，composer 上方没有 `LowcodeActionPicker`
面板（`conversation.input.dock` 槽位、`data-jdcloud-lowcode-actions`）。账号密码登录同样没有。

**结论（已用真实后端证实）**：面板的数据源恒为空，与渲染/槽位装配无关。

判定链：
1. `LowcodeActionPicker.tsx:55-61` —— `menuState.phase !== 'ready' || menuState.menus.length === 0`
   时 `return null`（静默）。
2. `jdcloud-auth-controller/src/client.ts:381` ——
   `menus: capabilities.menus.filter(menu => menu.agentPermissions.length > 0)`，
   而 `readWritePermissions(undefined)` 返回 `[]`，所以**只要节点没有 `agentPermissions`
   字段，就一定被过滤掉**。
3. 真实 `GET /api/oauth/currentUser`（beta.kindoucloud.com，HTTP 200）：
   - 138 个菜单节点，type 分布 `{1:25, 3:83, 4:12, 5:6, 6:12}`
   - type 3/4 共 95 个
   - **带 `agentPermissions` 键的节点：0**
   - 响应 `data` 根键只有 `menuList / userInfo / userPermission`
4. 换租户复验（switchCorp 到 `智慧沙石区域管控平台`、`东莞市水务工程监管平台` 后各读一次，
   最后切回 `测试`）：type 3/4 分别为 109 / 129，`agentPermissions` 命中数 **均为 0**。
5. 带不带 `?n=<ts>` 缓存参数结果一致。
6. 抽样 18 个表单的 `GET /api/visualdev/base/{menuId}`：`formData` 里也没有
   `agentPermissions`（0/18）。

**关键旁证**：JDCloud 门户前端 bundle（`static/js/app.e65dde4d.js`）里
`agentPermissions` 是**表单设计器属性**（i18n 标签 `agentPermissions: "Agent 权限"`，
配套 `addPermission:"增" / deletePermission:"删" / editPermission:"改"`，
默认值 `agentPermissions:[]`，与 `hideRules` 同级），
而运行时的按钮显隐走的是另一个数组：`getOpenBtn(e){return this.operationAuth.includes(e)}`。
即：`addData/editData/deleteData` 是平台真实的操作标识，但它挂在**表单设计配置**上，
不是 `currentUser.menuList` 的节点字段。

**测试为什么没拦住**：`apps/web/tests/jdcloud-ordinary-user.e2e.ts` 用的是**手写假后端**，
手工塞了 `agentPermissions: ['addData']` 等；全仓 `menuList` 出现处只有测试固件，
**没有任何真实响应的录制快照**。所以 CI 永远测不到这个字段在真实后端不存在。

**已排除的嫌疑**：
- 不是槽位遮蔽：`conversation.input.dock` 是 `list` 槽位，picker `order: -10`，
  todo `order: 0`、queue `order: 20`，都不会盖住它。
- 不是 transfer 专属：`ui-jdcloud-login` 的 administrator shadows 只遮
  `sidebar.settings` / `conversation.input.model` / `conversation.hero.agentPreset`，
  且本账号 `systemAdministrator: true`，设置入口在截图里可见。
- **不是**工作区里未提交的 `loginWithToken` 新增 `switchCorp`：
  实测 `getCorpList.corpId` 与 `currentUser.corpId` 都等于 `674fc864e36e5b7396e48dd1`，
  该调用是 no-op；而且三个租户的 `agentPermissions` 都是空的，切不切都一样。
- 时间线：`ui-jdcloud-lowcode-actions` 包本身在 `22e3f99a8c`（09-11）才创建，
  同一次提交引入 `agentPermissions` 过滤；`88fca7f5c1`（更早）在
  `conversation.input.dock` 上没有任何 JDCloud 贡献者。也就是说这个面板在真实后端下
  **从未渲染过**。

**可复跑诊断**：`.workbuddy-ai/tmp/diagnose-writable-menus.py [表单抽样数]`
（只读；从 `~/.dsh/.credentials.yaml` 取 token，不打印凭据）。

**待用户决策的修复方向**：
- 面板在空结果时给显式空态/原因，而不是静默 `return null`；
- 改数据源（按表单读设计器配置，或走 authority 接口）——需后端确认字段/端点；
- 管理员语义：`systemAdministrator: true` 是否应视为对全部 type 3/4 的隐式授权；
- 补一个真实响应录制固件，替换手写 `agentPermissions` 固件。
