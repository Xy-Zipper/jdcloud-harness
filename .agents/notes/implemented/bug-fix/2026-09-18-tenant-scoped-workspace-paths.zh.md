# Agent Note: 按租户范围登记 Workspace

Status: implemented

[English](2026-09-18-tenant-scoped-workspace-paths.md) | 中文

## 问题

Workspace 记录按租户和用户隔离，但注册表此前要求每个规范文件系统路径只能有一条记录。切换租户后选择前一个租户登记过的目录时，会解析到那个不可见记录，随后返回 `workspace/not-found`，而不是为当前范围创建私有记录。

## 决策

注册表继续存储规范路径，但允许所有者范围调用方明确请求同一路径的重复记录。Workspace 控制器会解析所选路径的全部记录，只复用当前租户用户范围拥有的记录，否则创建新记录。未认证或非所有者调用方继续使用原有的单路径幂等行为。

当同一路径存在多条记录时，启动不会把未记账的历史会话分配给其中一条，因为注册表没有租户凭据上下文。通过已认证会话流程创建的会话仍会附着在明确选定的 Workspace 记录上。

## 备选方案

**复用前一个租户的记录。** 拒绝，因为会暴露该租户的会话账本和问答历史。

**返回路径已被占用错误。** 拒绝，因为不同租户用户应能在同一服务器目录工作，同时保持 Workspace 数据隔离。

**在 Workspace 领域记录内保存所有者身份。** 本次修复拒绝，因为所有者凭据已经定义持久化范围，为创建隔离记录增加持久 schema 迁移没有必要。

## 后果

不同租户用户范围可以登记同一物理目录，并获得独立的 Workspace 与 Session 投影。对于重复路径无法推断所有者的历史会话，引导后会保持未分组，而不会被错误分配。`resolveByPath` 对不需要所有者消歧的调用方保持兼容；租户感知控制器使用 `resolveAllByPath`。
