# Agent Note: JDCloud 低代码对话工具与 Host 授权

Status: implemented

[English](2026-09-07-jdcloud-low-code-conversation-tools.md) | 中文

## 问题

JDCloud 浏览器 Prompt 准入会验证已存储的登录信息，但仅靠该检查不能告诉模型当前租户开放了哪些表单和流程。通用低代码工具可能接受猜测的菜单 id 或模型传入的权限，从而让其他调用方尝试 `/api/oauth/currentUser` 未授权的操作。服务地址和 Token 必须由 Host 持有，而建表需要更强的 `systemAdministrator` 授权，尽管其上游操作跨越多个请求。

## 决策

`@deepseek-ai/dsh-tool-jdcloud-lowcode` 插件为每个通过准入的浏览器用户 Prompt 推导一份授权快照，并在完整轮次（Turn）中使用该快照：

- 认证控制器在 Session 投递前检查 `/api/system/corp/getCorpList`。低代码插件随后通过控制器的 Host 认证请求方法调用 `/api/oauth/currentUser`，因此服务地址和 Token 不会进入浏览器状态、工具参数或模型上下文。
- 插件把当前用户 id、部门 id 和角色 id 合并为一次 `POST /api/system/permission/users/getMemberName` 请求，通过 `GET /api/system/permission/organize/selector` 加载当前租户的完整部门树，并递归筛选 `menuList`，仅保留 type `3` 表单和 type `4` 流程。当前用户必须能够解析；由于 current-user 数据可能保留已删除对象的 id，成员名称响应中不存在的部门或角色 id 会被省略。其持久化模型消息包含当前租户标识、`systemAdministrator`、已解析的 `currentMember` 选择值数组、带完整路径的扁平 `tenantDepartments`、菜单 id、名称、路径、类型和 `agentPermissions`；其余 current-user 响应不会进入消息。
- 工具执行要求当前开放轮次的快照、Host 本地当前租户 id 与快照一致，并要求每个请求的菜单 id 都存在于其中。租户不匹配时会在发起任何 JDCloud 网络请求前返回 `JDCLOUD_LOWCODE_TENANT_CHANGED`。读取操作只要求菜单可见。`jdcloud_lowcode_create`、`jdcloud_lowcode_update` 和 `jdcloud_lowcode_delete` 分别要求 `addData`、`editData` 和 `deleteData`；缺失或为空的 `agentPermissions` 列表不授予任何写操作。`jdcloud_lowcode_upload_file` 在结果用于新增时要求 `addData`，用于编辑时要求 `editData`，随后只会把完整摘要或模型可见的唯一八位摘要与调用 Session 的持久化用户消息中已有的文件和图片匹配。新增和更新执行器会重新加载实时字段定义，为每个拥有值的组件推导模型可见的 `writeType`，并在修改数据前拒绝不符合该类型的值。单选字段接受一个 id 字符串；多选字段（包括 `userSelect`、`depSelect` 和 `roleSelect`）接受 id 字符串数组，而不是读取时展开的对象。新增操作还会拒绝缺少的顶层或子表行必填值。
- 系统提示词指导模型根据用户提供的事实推导全部有依据的字段值，包括金额、日期、用途、说明和嵌套明细，而不是把推导限制在标题或自由文本。当字段指向当前申请人、请求人、提交人、报账人、员工、部门或角色时，模型会先使用对应的 `currentMember` 选择值，而不会把字段视为缺失，也不会搜索无关记录来推断身份。其他指定部门从 `tenantDepartments` 中精确选择，重名时使用完整路径区分。它以自然措辞询问确实缺失的信息，并在新增前通过一张确认表展示全部已描述字段。该表包含必填与非必填字段、嵌套字段以及附件字段。用于附件或图片字段的对话文件或图片在用户确认前保持待上传；上传工具随后把经过验证的图片字节或带文件名推导媒体类型的普通文件分块作为一个已认证的 multipart `file` 流式发送到 `/api/file/uploader`，校验 `{ name, url }`，并把该对象提供给字段数组。模型不能编造证据无法确定的不透明 id、其他选择值、附件引用或上传结果。
- `jdcloud_lowcode_create_table` 要求 `systemAdministrator === true` 和明确的授权对象 id。它通过三个有序上游请求创建菜单、写入可视化 schema 并分配权限。后续步骤失败时会报告已创建的菜单 id，而不会在没有事务的情况下删除先前资源。
- 其余工具用于描述字段、查询记录和读取单条记录。字段描述会增加推导出的 `writeType`；当上游子表容器提供 `children` 时，即使省略 `value`，字段描述也会接受它，叶子字段仍要求有效的类型值。type `4` 创建操作会提交流程任务；插件不公开审批、退回或驳回操作，因为三项写权限并不授权这些决定。
- JDCloud 业务码 `600`、`601` 和 `602` 会通过认证控制器清除已存储登录，并使操作以需要认证失败。其他业务错误或传输失败会保留登录。

## 备选方案

- **复用完整的外部 `@jdcloud/api` 包。** harness 只需要少量由 Host 持有的请求及不同的授权时点，复制其包结构会引入无关的浏览器假设和 API 表面。
- **仅在模型选择工具后获取能力。** 模型将不得不猜测菜单名称和 id，而影响其决策的能力信息也不会成为持久化 Session 输入。
- **公开完整的 current-user 响应。** 完整资料和菜单数据会增加模型 token，并暴露对 type `3` 或 type `4` 操作没有帮助的字段；快照只保留填写匹配组件所需的当前选择 id 和名称。
- **从既有业务记录推断人员或部门。** 历史记录可能属于其他用户或部门，因此 Host 通过 current-user 和成员名称响应解析当前账号，并通过部门选择器解析租户部门选择值。
- **把提示词指导或工具 schema 当作授权。** 两者都是面向模型的描述，其他执行器调用方可以绕过；发送每个请求的 Host 操作会执行权限校验。
- **仅由确认提示词检查字段。** 其他调用方和错误的模型输出都可能绕过对话指导，因此新增和更新执行器会根据当前上游字段定义校验提供的组件值类型；新增执行器还会在写入前校验必填值。
- **自动回滚部分创建的表。** 上游序列没有事务，在后续失败状态不确定时删除先前资源可能破坏服务端已经接受的资源；该包会报告部分创建状态，以便显式恢复。

## 后果

- 每个通过准入的浏览器 Prompt 都会在租户列表准入请求之后增加一次 current-user 请求、一次批量成员名称请求和一次部门选择器请求。同一轮次中的工具续步复用已记录快照，不会重复发现能力、成员或部门。每次通过菜单授权的新增或更新尝试都会在校验或修改前增加一次实时字段定义请求。
- 模型只看到当前响应开放的表单和流程。切换租户会使该快照失效，直到下一次通过准入的浏览器 Prompt；轮次中发生的其他权限变更也会在该 Prompt 生效。
- 新增对话可以根据已知事实、准确的当前成员选择值和准确的租户部门选择值填写受支持字段，无需提出不必要的补充问题；完整确认表仍会展示附件等非必填值。已确认的对话文件和图片可以成为 JDCloud 附件值，同时不会暴露 Token；缩短的模型可见摘要只有在 Session 中唯一匹配一个附件时才会成功。模型从读取结果中复制的展开部门或角色对象不能作为写入值发送：Host 要求描述结果中的 id 字符串或 id 字符串数组。即使模型在确认中遗漏必填值，Host 请求仍会被阻止。
- 读取访问与每项写授权保持独立。菜单可见性绝不意味着新增、编辑、删除或建表权限。
- 后续请求失败时，建表可能留下菜单或 schema；运维人员可用返回的菜单 id 检查并修复该部分资源。
- 该包明确放弃流程审批操作和任意低代码 API 访问。包 README 负责说明面向使用方的行为与限制。
